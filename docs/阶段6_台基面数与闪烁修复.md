# 阶段 6 · 台基面数修复与转视角条纹闪烁

改动文件：`js/gf-parts.js`（仅 `platform()` 与踏跺段，新增模块内 `rectRing` / `loftRect` / `capRect`）。
渲染器、装配、预置、UI 一行未动。

## 1. 症状

台基（`GF.parts.platform`）在 320 档（`ppm ≥ 240` → det 3）侧看时：

- 每道线脚的交界出现**一条条白色细虚线**，随视角转动而游走；
- 局部出现**棋盘／斜纹状的色块闪斑**（御路石、束腰莲瓣带最明显）；
- 拖动旋转的交互帧上线纹**整排忽隐忽现**，松手出全精度帧又回来。

三档形制都能复现，须弥座最重，毛石台最轻（只有台面与立面交界处）。

## 2. 根因（三条，逐条对应一种"闪"）

1. **共面盖面对叠**。旧实现是几十个 `box` / `taper` 叠出来的，每个 `taper` 自带顶盖和底盖。段与段一叠，就必然出现"两张同高、同尺寸的盖面"——同一个平面画两遍。`depth` 判定是 `z <= depth[p] → 跳过`（严格大于才写），两张面深度相等时谁先到谁赢，三角形遍历顺序一换，赢家就换，于是出现 1 px 宽的白虚线，并随视角在亚像素级来回翻。实测 `qing ppm=320` 台基内部共面重叠面对 578 对、合计 2372.7 m²，最大单项是"圭脚顶面 × 下枋底面"150.7 m²。
2. **亚像素薄板**。侧面石（0.6×0.22、16 mm 缝、`inset` 随高度变，压在斜收分面上近似共面）、缝底（3 mm）、铺地（0.28 m 一块、8 mm 缝）、台基莲瓣（0.26×0.1×0.02 小盒）、玛瑙柱（凸出 1.5 cm）都是毫米级几何，常规密度下投影面积 0.6~2.6 px。`js/gf-render.js:523-524` 的交互轻量帧规则是 `if (lightFrame && Math.abs(area) < 0.55) continue;`——这类面**在拖动帧里被整片丢掉、松手帧又画回来**，表现就是"整排细纹忽隐忽现"。这是闪烁里"忽隐忽现"的那一半。
3. **踏跺与御路石／垂带同面**。御路石与踏跺立面的 ±z 完全同 z、垂带内侧与踏跺 ±x 完全同 x、相邻踏跺侧面同 x，全部精确共面 → 同第 1 条。

## 3. 改法

两条硬规矩：**内部不封盖面**、**小于 4 cm 的装饰不落几何**。

- 台身改为**断面环 loft**：`loftRect(mb, cx, cz, rings, tag)`，`rings` 自下而上 `{y, w, d, m}`，相邻两环之间只出 4 条侧板，一张盖面都不封；两环同高、只收尺寸时这 4 条侧板就自然成为一道水平压边。台面用 `capRect` 单独一张 2 面板。
- 须弥座 9 环：圭脚 0 / 0.12（`stoneDark`）/ 0.26（`stone`）/ 0.33 / 0.40（低档 `marble` 腰带）/ `yb` / `yb+0.1` / `h`（`marble`），`yb = max(0.5, h-0.32)`。原来的六层线脚 + 束腰 + 圭脚各自带盖面的写法整段删除。
- 直台基 5 环：陡板 `0 → rim`、阶条石外挑 5 cm（`W+0.1`）、台面内收 4 cm，台面用 `slabTop`。
- 毛石台 3 环 + 台面 `stoneBTop`；`det ≥ 3` 才补真石块，**每块只出一张正面 quad（外贴 5 mm）**，不再是小盒。
- 装饰全部交给材质肌理：`stone/stoneDark/marble/slab` 走 `mason`（0.33 m 横缝、0.66 m 错缝、3.2 cm 缝宽，只对 `|ny| < 0.62` 的立面生效），台面走 `slabTop/stoneBTop` 的 `paving`（0.9×0.6、3 cm 缝，只对 `|ny| > 0.6`）。肌理是逐像素算的，不会随视角翻转，也就不可能闪。
- 须弥座 `det ≥ 2` 保留构造感：束腰玛瑙柱、四角角柱改成**贴面 quad**（外贴 4 mm），一副 4 面，不再是几十个盒子。
- 踏跺：御路石四周外放 1.2 cm（不再与踏跺立面同面）；每级踏步比上一级外放 1.5 cm（侧面不再同 x 平面）；垂带内侧压进 2 cm、两端各外放 1.2 cm；`det ≥ 3` 的踏面石与暗缝从盒子改成单张 2 面 quad；**最下面一级高度为 0 的退化盒子直接跳过**（原来白送 12 个退化三角面，顶底精确重合）。

## 5. 怎么验

`coplanar-base.js`：把台基相关三角面按平面量化分组，组内两两用 Sutherland–Hodgman 求真实 2D 重叠面积，超过 1 cm² 记一对。

```bash
# 需要 Node，不需要浏览器；cli/modules.js 给出同一批源码清单
node coplanar-base.js qing 320 after
node coplanar-base.js temple5 320 after
node coplanar-base.js siheyuan 200 after
```

`count-report.js` 出第 4 节那张面数总账；`node cli/preset-audit.js` 仍是 64 套 error 0 warn 0；`node --check js/gf-parts.js` 过。

基线对照：把旧版文件另存（`git show HEAD:js/gf-parts.js > /tmp/before.js`），用环境变量 `PARTS_OVERRIDE=/tmp/before.js` 重跑同一脚本即可得到"前"列。

肉眼比对用固定取景（`focus:false`，取景只由外包围盒决定，两版只差 1 cm 级，裁剪窗口按比例取 → 基本像素对齐），150 档同一窗口下：旧版线脚交界是一串白虚点 + 局部斜纹斑，新版是连续实边。

## 6. 取舍与遗留

- 须弥座**束腰莲瓣不再落几何**：低档（det < 2）改由一条汉白玉腰带（`marble`）暗示，高档保留玛瑙柱与角柱的贴面。想要浮雕莲瓣回来，只能做成"贴面三角形"（每瓣 1 面），不能再回小盒——小盒就是闪烁源。
- 侧面石 / 铺地 / 踏面石不再是真的石块几何，改由材质的砌缝肌理表达。优点是永不闪烁、面数几乎为零；代价是**立面砖缝只有 `mason` 那一套 0.66 m 错缝节奏**，台面只有 `paving` 的 0.9×0.6，不能再按构件单独调块大小。
- `o.grain`（按三角面取哈希给 ±6% 亮度）会让每个 quad 的两个三角面亮度不同，大平面上有一条对角分界线。这是全项目既有行为，不是台基引入的，本轮没动。
- `js/gf-core.js` 的 `marble: ['#8f8c83', '#b0ad a3', '#d2cfc4']` 里中间那个值带空格、是非法 hex，汉白玉中间级色阶取不到正确颜色。属台基立面主色，但不在本轮范围内，未修。
